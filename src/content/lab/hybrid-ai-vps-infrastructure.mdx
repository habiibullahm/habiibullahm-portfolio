Deep dive and technical devlog into engineering a hybrid cloud-local AI agent architecture.

## Run it

By hand, in a window that stays open:

```powershell
powershell -ExecutionPolicy Bypass -File .\start-antigravity-proxy.ps1
```

Automatically at every Windows login, set up once:

```powershell
powershell -ExecutionPolicy Bypass -File .\install-startup.ps1
```

Needs `node` and `ssh` on PATH, and `ssh bot-vps` must log in without a password prompt. The PC has to stay on; if it is off, Antigravity fails (Strict Proxy) and other providers are unaffected.

## Check it

Local proxy, from the PC:

```powershell
curl.exe -sS -m 15 -x http://127.0.0.1:18080 https://ipinfo.io/org
```

Through the tunnel, from the PC:

```powershell
ssh bot-vps "curl -sS -m 15 -x http://127.0.0.1:18081 https://ipinfo.io/org"
```

Both should print Telkom Indonesia. Tencent means the tunnel is down.

## If something breaks

- **Proxy CONNECT aborted:** the proxy on the PC is not running. Start the script again.
- **Remote port forwarding failed:** port 18081 is taken on the VPS. Change it in the script and in the 9Router proxy URL together.
- **403 is back:** the tunnel is down. Run the check before testing again.

## Limits

This is a stopgap. A lasting fix needs an always-on proxy at a normal ISP address. Antigravity through 9Router uses an unofficial OAuth session, so Google may limit or block the account. It is also not proven whether Google rejects the VPS because of the datacenter range or for another reason; the 403 body was never captured.
